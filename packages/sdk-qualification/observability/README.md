# Local observability qualification

`bun run observability:check` typechecks all recipes and runs each in fresh Node and Bun processes, with sampled and unsampled cases. `BEACHSIDE_NODE_BINARY` selects a particular Node executable. The default is `node` on PATH. There are no live provider calls, account changes, real vendor ingestion, or vendor UI checks.

Pinned versions and copyable setup are documented in the [public tracing guide](../../../apps/docs/src/content/docs/docs/observability.mdx). Official Sentry 11 released APIs were verified against installed declarations and the current official pipeline documentation, rather than the earlier bridge direction in the proposal. Complete public examples are compiled from the actual guide, rendered from checked source files, and executed with provider/transport boundaries replaced. Additional injected connection and client-close failures verify telemetry shutdown in each complete example. Native Sentry OpenTelemetry bridges are checked on Node and Bun. Native dd-trace 6.17.0 is checked on Node with a local Agent stand-in and decoded MessagePack exports; Bun uses the OTel-to-Agent/Collector OTLP path.

The qualification receiver accepts JSON OTLP over local HTTP. It validates parent/phase relationships and excludes canary secrets. Sentry runtime packages are tested independently with a stub transport, checking one event-scoped sanitized issue alongside an unrelated checkout error retaining its message, stack and tags, including trace/error/operation correlation when sampling drops all spans. Default integrations remain enabled. Throwing span processors and a failing local OTLP collector also verify that provider results, one-submit behavior and cleanup survive telemetry failures. The direct adapter HTTP fixture uses real `instrumentation-http` with Node `http.request`, including Bun's compatible implementation. Native Bun fetch auto-instrumentation and remote backend presentation remain unverified.

Root SDK bundle comparison against parent 78a2fe3 (same Bun target, package imports external): 35,759 bytes before versus 56,750 bytes after; gzip 8,072 versus 12,852. This includes wrappers and diagnostics. Production adds only the external shared `@opentelemetry/api@1.9.1`, about 1.0 MB installed including declarations, source maps and both module formats. No OTel SDK/exporter, Sentry or Datadog SDK enters the SDK/client production graph. Package size acceptance budget is below 32 KB additional uncompressed root code, 8 KB gzip, and 1.5 MB installed API files. The direct root API/context is checked by packed consumers.

The SDK scope uses its public package name and manifest version. Providers remain independent of OTel. This deliverable covers direct SDK tracing/diagnostics and direct vendor recipes (updated specification units 1–2). Metrics and structured events remain a later unit.
